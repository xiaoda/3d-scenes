# 中世纪欧式小镇：精简设计开发计划

> 创建：2026-10-07｜更新：2026-10-08｜最新状态：P0、第一批资产与酒馆立面升级已获阶段效果认可；用户授权进入 P2，小街角首版已实现，等待场景评审。不是最终全场景画质验收。下文保留最初规划和历史检查点。  
> 已确认方向：自然写实的欧式古镇，不做具体历史地点的精确复刻；首轮仅使用免费资产。  
> 执行说明：本文件是精简路线图；资产与视觉方向确认后，再用 executing-plans 技能按检查点推进详细实施。

**目标：**先做一个画质足够好、可以自由走动和转头的小镇街角，而不是一个面积很大但像技术演示的城镇。  
**架构：**高质量资产离线整理，浏览器加载展示；场景内容、渲染和行走控制分开。先验证画质，再确定最终运行路线。  
**技术候选：**Blender + GLB／PBR 资产；网页原生路线暂以 TypeScript、Vite、Three.js 验证，碰撞按需使用 Rapier。不预先锁死引擎。

---

## 1. 场景设计

| 项目 | 首版范围 |
|---|---|
| 空间 | 约 20 × 30 米：一段短街、一个转角、小院落；必要时进一步缩小 |
| 建筑 | 2–4 栋同一建筑传统的木骨架／灰泥／石砌房屋；不混用多个风格包 |
| 视觉焦点 | 街角酒馆入口；招牌、门窗凹槽、石阶和少量生活道具 |
| 氛围 | 固定晴天、偏暖侧光，材质与色彩克制；不靠浓雾遮盖缺陷 |
| 细节 | 优先石路、墙体、木梁、屋瓦；少量桶箱、藤蔓和杂草辅助 |
| 边界 | 通过转角、院门和建筑自然限制可达范围；不可到达处只作背景 |
| 真实性 | 原创布局、参考真实建筑逻辑；不宣称精确复刻某个历史地点 |

**首版不做：**室内探索、NPC、任务、战斗、车辆、昼夜天气循环、完整小镇、复杂编辑器。

## 2. 技术路线与取舍

| 路线 | 本次定位 | 主要代价 |
|---|---|---|
| **成熟资产 + Blender 整理 + 网页原生渲染** | 优先验证；便于本地浏览器体验与轻量交付 | 需要处理材质导出、光照与性能；资产本身必须合格 |
| UE + Pixel Streaming | 若优质资产到位后，网页方案仍达不到关键画质要求，再作对照 | 需要渲染主机、串流与运维，不能当作纯静态网页 |
| 3DGS／混合扫描 | 仅在获得合适授权扫描或连续多视角数据时试验 | 覆盖、近看、碰撞和编辑能力需另验；本期不作为必需项 |

数据流：**参考图 → 授权资产 → Blender 整理／必要烘焙 → GLB 与纹理 → 浏览器场景 → 固定机位和走动验收。**

关键决策：代码负责组织、交互与优化，**不默认从零生成全部最终建筑、植物和材质**。付费资产先确认预算与许可，不自动购买。

## 3. 开发顺序与检查点

| 阶段 | 主要工作 | 交付与进入下一步的条件 |
|---|---|---|
| **P0：锁定视觉目标** | 选 3–5 张参考，确定建筑风格、光照和主要构图；画简易平面布局 | 一页参考板与布局；用户认可方向 |
| **P1：验证实际资产** | 导入一栋建筑、一块地面及关键道具；检查近景、背面、材质与许可 | 实际资产样板；不能仅凭商店宣传图通过 |
| **P2：做品质样片** | 搭小街角，固定光照，精调比例、材质尺度、接地、明暗和场景层次；加入最小行走能力 | 浏览器内可绕看、近看的样片；先验画质，不扩地图 |
| **P3：完善体验** | WASD、鼠标转头、拖动备用操作、碰撞、重置位置；加载失败提示与失焦暂停 | 在已制作区域内稳定体验，不穿墙、不掉出场景 |
| **P4：优化交付** | 纹理／几何优化、实例化、必要 LOD；实际 GPU 与帧时检查 | 本地 HTTP 预览、固定视角截图、问题清单和验收记录 |

**排期原则：**P0／P1 先确定资产可得性与制作量，再估整体工期；P2 最多先做两轮重点修正。不先承诺“几天内必然达到目标画质”。

## 4. 验收标准

- **画面：**检查入场主视角、约 1 米近景、侧后方、转角和连续走动；主要物件不能仍是占位质量。
- **材质：**石材、木材、灰泥能清楚区分；门窗有厚度，地面与建筑接触自然，重复纹理不抢眼。
- **风格：**尺度与年代气质一致，不能像几个素材包随意拼装。
- **操作：**可自由移动、旋转、回头和重置；加载完成前不允许进入缺失区域。
- **性能：**在用户实际浏览器和 GPU 上记录分辨率、画质档及帧时；以 1080p 下稳定约 30 FPS 为初始目标，不是承诺。先缩范围和优化，不直接牺牲近景品质。
- **通过含义：**用户确认“愿意把这个完成度作为最终成品标准”，才算品质基线通过；“先这样继续”只算阶段认可。

**止损规则：**关键资产拿不到，先调整来源或范围，不静默改用低质量程序模型。连续两轮仍像玩具／示意场景，停止加功能，判断该换资产、美术方法还是渲染路线。

## 5. 最小工程组织与验证

网页候选验证通过后，再创建：

- 资产与场景：public/assets/town/、src/scene/town.ts。
- 渲染与行走：src/engine/renderer.ts、src/engine/walk.ts。
- 来源台账：docs/assets/town-sources.md，记录作者、许可、下载与修改信息。
- 验收：tests/walk.test.ts 检查移动／边界逻辑；docs/reviews/town-quality.md 记录同机位图、实机结果和剩余问题。

功能逻辑按“先写失败测试 → 最小实现 → 回归”推进；单元测试不代替浏览器截图与视觉验收。

本地预览仅监听 127.0.0.1，后台启动、不抢焦点；不默认上传公网。先实际导入并检查资产许可，不将私有参考资料放入可访问的静态目录。
